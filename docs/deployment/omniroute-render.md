# OmniRoute + ElevenLabs on Render

This guide deploys OpenJarvis on Render with chat inference routed through an
[OmniRoute](https://github.com/diegosouzapw/OmniRoute) gateway and spoken
replies produced by ElevenLabs. No credential is stored in the repository:
everything is an environment variable (see `.env.example`).

## How it fits together

```
Browser (HTTPS, microphone) ──► OpenJarvis on Render ──► OmniRoute  (OpenAI-compatible /v1)
                                       └────────────────► ElevenLabs (text-to-speech)
```

OmniRoute exposes an OpenAI-compatible API (`POST /v1/chat/completions`, SSE
streaming, `GET /v1/models`, Bearer auth). OpenJarvis talks to it through the
`omniroute` engine, so streaming, tool calls and conversation history work like
any other OpenAI-compatible engine.

## 1. Make OmniRoute reachable from Render (required)

OmniRoute running on your PC listens on `http://localhost:20128`. **Render's
servers cannot reach `localhost` on your machine**, so a Render deployment needs
a public HTTPS URL for your OmniRoute. Options:

- Run OmniRoute on a host with a public HTTPS address (a VPS, or another Render
  service) and protect it with its API key.
- Or expose your PC's OmniRoute through a tunnel (for example Cloudflare Tunnel
  or ngrok). Your PC must stay on and online while the tunnel is in use.

Whatever you choose, treat the URL as a secret-adjacent value and keep
OmniRoute's API-key requirement enabled so the endpoint is not open to the
internet. Confirm it works from outside your network before deploying:

```bash
curl -H "Authorization: Bearer $OMNIROUTE_API_KEY" "$OMNIROUTE_HOST/v1/models"
```

The response lists the model IDs/combos you can use for `OPENJARVIS_MODEL`.

## 2. Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `OPENJARVIS_ENGINE` | yes (blueprint sets `omniroute`) | Inference engine |
| `OMNIROUTE_HOST` | yes | Public base URL of OmniRoute (`https://host` or `https://host/v1`) |
| `OMNIROUTE_API_KEY` | yes | OmniRoute Bearer key |
| `OPENJARVIS_MODEL` | yes | Model ID or combo from `GET /v1/models` |
| `OPENJARVIS_TTS_BACKEND` | yes (blueprint sets `elevenlabs`) | Selects ElevenLabs for voice output |
| `ELEVENLABS_API_KEY` | yes | ElevenLabs key |
| `ELEVENLABS_API_KEY_FALLBACK` | no | Backup key, see below |
| `ELEVENLABS_VOICE_ID`, `ELEVENLABS_MODEL` | no | Voice / model overrides |
| `OMNIROUTE_MAX_RETRIES` | no | Transient-error retries (default 2, `0` disables) |
| `OPENJARVIS_API_KEY` | generated by Render | Protects the OpenJarvis API |

`OMNIROUTE_HOST` has no baked-in production value; the `localhost:20128` default
only applies to a locally running OmniRoute.

## 3. Deploy

1. Push this repository to your GitHub account.
2. In Render choose **New → Blueprint Instance**, select the repo, and fill in
   the prompted values (`OMNIROUTE_HOST`, `OMNIROUTE_API_KEY`,
   `OPENJARVIS_MODEL`, `ELEVENLABS_API_KEY`).
3. Wait for `/health` to turn healthy, then open the service URL.
4. Optional variables (`ELEVENLABS_VOICE_ID`, `ELEVENLABS_MODEL`,
   `ELEVENLABS_API_KEY_FALLBACK`) can be added later in the dashboard.

## Reliability behaviour

- **OmniRoute:** requests that get HTTP 429/502/503/504 or fail to connect are
  retried (default 2 times, short backoff, honouring `Retry-After`). Retries
  happen before any response bytes are consumed, so a streamed answer is never
  replayed half-way. Authentication errors and other 4xx are not retried.
- **ElevenLabs backup key:** if `ELEVENLABS_API_KEY_FALLBACK` is set it is tried
  only when the primary key is rejected (401/403) or ElevenLabs is
  down/unreachable (5xx, network error). It is **not** used for quota or
  rate-limit responses (402/429): rotating keys to get around provider limits is
  not supported and may breach ElevenLabs' terms.

- **Startup:** because `OPENJARVIS_ENGINE=omniroute` names the engine explicitly,
  OpenJarvis never silently substitutes another engine. At boot it checks
  `GET <OMNIROUTE_HOST>/v1/models` with your key; if OmniRoute is unreachable or
  rejects the key, `jarvis serve` exits ("No inference engine available") and
  Render shows the deploy as failed or restarts it. Check the Render logs and
  your OmniRoute URL/key first.

## Speech input (microphone)

The existing web UI records audio in the browser (`MediaRecorder`) and sends it
to the server's `/v1/speech/transcribe` endpoint. It does **not** use browser
built-in speech recognition. This deployment installs no speech-to-text engine
(local faster-whisper does not fit Render's 512 MB free instance, and cloud STT
would add another paid dependency), so with the default image the microphone
button reports that no speech backend is available and the rest of the app
(typing, spoken replies) works normally. Adding browser-native recognition would
be a separate frontend change.

!!! note "HTTPS and microphones"
    Browsers only allow microphone access on HTTPS pages. Render serves HTTPS by
    default.

## Free-instance limits

See [Deploy on Render](render.md): the free filesystem is ephemeral and the
service spins down when idle, so the first request after a pause is slow.

## Verification checklist (run after deploying)

- [ ] `curl -H "Authorization: Bearer $OMNIROUTE_API_KEY" $OMNIROUTE_HOST/v1/models` lists models from outside your network
- [ ] Render service `/health` returns healthy
- [ ] The chat page sends a message and a streamed reply appears
- [ ] The conversation keeps context across several turns
- [ ] `GET /v1/speech/tts/health` (with your `OPENJARVIS_API_KEY`) reports available
- [ ] Spoken replies play in the browser
- [ ] Temporarily set a wrong `OMNIROUTE_API_KEY` and confirm the UI shows a clear error rather than hanging
